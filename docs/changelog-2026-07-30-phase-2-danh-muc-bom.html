BE 9. BomRevision + 5 bảng dòng con Phức tạp nhất

bom_piece / bom_part / piece_bom / part_bom / consumable_bom — 2 controller (ProductBomRevisionsController cho create/list theo product, BomRevisionsController cho mọi thao tác theo id riêng của revision, kể cả 5 sub-resource).

State machine DRAFT → ACTIVE → RETIRED

Mọi create/update/delete trên 5 bảng dòng con đi qua assertDraft() — 409 nếu revision không còn DRAFT. Revision chỉ xoá được khi còn DRAFT (ACTIVE/RETIRED là lịch sử vĩnh viễn mà production_order ở P7 sẽ ghim bomRevisionId vào).

activate() an toàn dưới tải song song

Transaction retire-ACTIVE-cũ-rồi-activate-mới cho cùng 1 product. Bộ chặn concurrency thật sự là partial unique index bom_revision_one_active_per_product đã thêm sẵn ở migration — không phải lock trong code: nếu 2 activate() chạy đua nhau, DB tự chặn cái commit sau (409 qua filter Prisma toàn cục).

Phát hiện khi viết code: bom_piece/bom_part không có cột mfg_product_id, và composite-FK của piece_bom/part_bom chỉ chứng minh dòng đó trỏ đúng 1 revision thật — không hề đảm bảo piece/part được gán vào có cùng product với revision. Bù bằng assertSameProduct() ở tầng service cho cả 4 bảng liên quan (400 nếu lệch product).

activate() dùng permission APPROVE

Coi là state transition/duyệt, không phải sửa field thường — khác với các Patch khác trong module dùng UPDATE.

Verify bằng chính BomRevisionsService thật trên DB thật — 10 kịch bản, tất cả đúng: tạo DRAFT → thêm bom_piece cùng product (OK) / khác product (400) → piece_bom composite-FK + label đúng → consumable_bom từ chối STEEL_BAR / nhận PAINT → activate → sửa dòng con sau activate bị chặn (409) → xoá revision ACTIVE bị chặn (409) → tạo rev2 + activate rev2 → rev1 tự động chuyển RETIRED, chỉ đúng 1 ACTIVE.

BE 11. API Reference cho FE

Toàn bộ endpoint mới, để FE tra khi nối dây từ mock sang thật. Quy ước chung áp dụng cho tất cả.

Quy ước chung: base path /api/v1/... · header Authorization: Bearer <jwt> · mọi response thành công bọc trong { success: true, data, timestamp, path, statusCode } — FE đọc field data. Danh sách phân trang: query page,limit,sortBy,sortOrder,search, trả { data: [...], meta: { page, limit, total, totalPages } }. Mọi id (kể cả trong body request) là string, không phải number — domain P2 dùng bigint, JSON không biểu diễn được số nguyên lớn an toàn.

12. Việc còn để ngỏ

  • Seed admin user vẫn báo lỗi cuối pnpm seed — vô hại (các bước trước đã ghi DB xong), nhưng nếu muốn hết thông báo lỗi thì cần thêm SEED_ADMIN_EMAIL/SEED_ADMIN_PASSWORD vào .env (đã có sẵn admin@demo.com, không bắt buộc tạo thêm).

  • Phase 2 đã xong, Phase 3 (Ledger Core) chưa bắt đầu — theo đúng build-order của roadmap, bước kế tiếp là StockLedger + trigger fn_sync_stock_quant() + StockQuant, có thể chạy song song với P4 (Bán hàng).
